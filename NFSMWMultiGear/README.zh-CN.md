# NFSMW MultiGear v1.0.0 - Reforged 启动验证与设备绑定

这个版本为配置中明确列出的变速箱提供第 8 至第 12 个前进挡。第 8 挡使用
已经验证的布局空槽；第 9-12 挡使用插件自己的 sidecar，不改写游戏布局中
第 0x70 字节之后的字段。配置文件没有列出的车辆完全透传原游戏逻辑。

每个新增挡位可以单独设置齿比和动力倍率。倍率通过该挡的实时
`GEAR_EFFICIENCY` 查询生效：`1` 保持原生第 7 挡的传动效率，`1.2` 为 1.2 倍，
`0.8` 为 0.8 倍。它不改变齿比决定的发动机转速/车速关系。插件不再把倍率
写入游戏会整表扫描的共享效率槽；倍率只在已验证的实时动力调用点，并且第
8-12 挡确实是当前挡位时应用。因此它不应改变倒挡、空挡或第 1-7 挡的动力，
降回低挡后也不会残留。

HUD 适配包括原版比赛/直线加速 HUD，以及用户当前安装的精确
`CustomHud.asi` v1.8.2。CustomHud 的 10、11、12 挡会使用现有 `digits.dds`
分别绘制两个数字；无需替换贴图。其他 CustomHud 版本不会被盲目修改，只会在
日志中记录并安全跳过兼容层。

当前可验证范围是手动换挡。自动挡原生控制器有多处直接访问固定数组，当前版本
对第 9-12 挡采取 fail-closed，避免错误换挡或越界；因此不要把自动挡的行为当作
已完成支持。

## 运行环境

- 仅支持经典 ASI Loader，使用 `NFSMWMultiGear.asi`。
- 游戏与插件都是 32 位，必须使用 Win32/x86 ASI。
- 当前只支持下面精确版本的 Reforged 主程序；文件名可使用
  `Need For Speed MW-Reforged.exe` 或原始的 `speed.exe`。
- 不支持热卸载或热重载；更换 ASI 或配置前必须完全退出游戏。

```text
文件大小  6,135,872 bytes
MD5       FCBBAC633822546B4B5D86DB5F2F03DE
SHA-256   188FB0748DA83AE54126D1F674AB81D8B8B1CCF9D57311A46CC76D8BF71BCD8A
```

## 启动验证与设备绑定

主程序末尾包含 64 字节结构化签章，验证代码为 `868086`。插件在读取变速箱配置、
安装 MinHook 或修改 HUD 代码之前，会核对文件名、大小、MD5、完整 SHA-256、签章
字段、原始游戏映像摘要、PE 字段和所有待 Hook 地址的代码签名。任一项不符都会
停用插件。

首次验证通过后，插件会在游戏目录的 `SCRIPTS` 中原子创建
`NFSMWMultiGear.device.json`。硬件 ID 由 SMBIOS System UUID、Windows
MachineGuid 和系统卷序列共同计算。绑定内容先用 Windows DPAPI 的
`CRYPTPROTECT_LOCAL_MACHINE` 加密，再把密文逐字节转换为大写十六进制，文件只保留
如下格式的 JSON 外壳，因而不会直接显示硬件 ID、主程序名或其他明文绑定字段：

```json
{
  "schema": 2,
  "encoding": "DPAPI-LOCAL-MACHINE-HEX",
  "ciphertext_hex": "..."
}
```

以后启动时插件会严格解析外壳、还原十六进制、用本机 DPAPI 解密，并逐字节核对
规范绑定内容。文件损坏、手工改动、无法解密或设备变化时，插件拒绝运行且不会
覆盖原绑定。v0.8.0 的 schema 1 明文文件在首次升级时只会先与当前设备严格匹配，
匹配后原子迁移为 schema 2；不匹配的旧文件不会被覆盖。

这是本地安装连续性绑定，不是联网授权。十六进制本身只是编码，DPAPI 才提供本机
范围的保密与完整性；删除 JSON 仍会使下一次合法启动重新执行首次绑定。如果需要
防止把整套文件复制到另一台电脑后重新绑定，必须另加服务器或离线私钥签发流程。

## 配置格式

第二列是前进挡数量。其后从第 8 挡开始，为每一挡依次填写一组
`齿比 动力倍率`：

```text
sf90_top 12 0.639 1 0.622 1 0.611 1 0.600 1 0.585 1
```

也可以使用 `forward=12`。如果按游戏原始数组槽位填写，则用
`slots=14`、`total=14` 或 `ratio_count=14`；14 个槽位包含倒挡、空挡和
12 个前进挡。请求 12 挡时必须提供 5 组齿比/倍率；倍率必须是有限正数。
请始终写完整的成对格式，缺少的值不会由插件猜测。

旧版纯齿比行仍兼容，并把每挡倍率默认为 `1`：

```text
sf90_top 12 0.639 0.622 0.611 0.600 0.585
```

由于纯齿比旧格式仍受支持，截断的成对格式可能在词法上与一条完整旧格式相同。
因此不要逐对试填，应一次写齐目标挡位的所有齿比/倍率。

名称是忽略大小写的精确匹配，没有通配符或默认项。要关闭某辆车，只需注释或删除
它的配置行。

## 手动测试

1. 完全退出游戏，暂时停用其他会挂钩变速箱的插件。
2. 使用随 v1.0.0 交付的 Reforged 主程序（可命名为
   `Need For Speed MW-Reforged.exe` 或 `speed.exe`），并将
   `NFSMWMultiGear.asi` 放入游戏的 `SCRIPTS` 目录；保留自己的配置文件。
3. 首次启动后确认 `SCRIPTS\NFSMWMultiGear.device.json` 已自动生成。
4. 使用手动模式进入比赛，依次执行 7->8、8->9、9->10、10->11、11->12。
5. 确认 HUD 顺序显示 `8、9、10、11、12`，再逐级降挡并正常退出。
6. 先以倍率全部为 `1` 记录第 1-7 挡的转速、车速和驱动力基线；再只把一个高挡
   改为明显但合理的非 `1` 值。确认倍率只在对应的当前高挡生效，第 1-7 挡表现与
   基线一致，并在高挡降回低挡后立即恢复。修改配置前必须退出游戏。
7. 正式版不会创建或写入 `SCRIPTS\NFSMWMultiGear.log`。如需诊断输出，须使用
   单独的开发构建；正式版仍会在验证失败时安全停用，不会继续安装 Hook。

数字变化本身不等于成功；高挡必须仍有驱动力，且转速/车速关系符合配置齿比。
受轮胎抓地力、风阻、转速限制等影响，车辆加速度不一定与倍率严格线性变化。

## 正式版运行策略

正式版默认关闭诊断日志，不会生成或覆盖 `NFSMWMultiGear.log`。启动验证、
`868086` 签章、设备绑定、配置解析和 Hook 安全检查仍照常执行；任一检查失败
都会安全停用插件。旧日志文件可以保留，不会被正式版改写。
