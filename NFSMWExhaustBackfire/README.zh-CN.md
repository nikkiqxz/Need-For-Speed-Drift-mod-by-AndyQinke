# NFSMW Exhaust Backfire

《Need for Speed: Most Wanted》(2005) 排气回火增强插件，当前版本为
`1.1.15` 正式版。

## 当前已经完成

- 全局硬门槛为 4000 RPM：转速不超过 4000 时，换档、持续红线和 NOS 边沿
  均不能生成新的回火事件，尚未播放的火焰/音频队列也会被取消。
- 每次实际升档只做一次三选一判定：左右同步各一发 22.5%，随机一侧先喷、
  另一侧延后 300 ms 各一发 17.5%，不喷 60%。有效驾驶降档只要 RPM 严格
  大于 4000，就独立使用固定 80% 触发率；成功后仍按 45:35 的相对权重选择
  同步或顺序模式。松开油门溜车时主动降档同样有效，不再要求油门、刹车或
  手刹输入。
- 左右排气节点总数少于 4 时维持上述行为。总数达到 4 后，同步模式会在
  左右各随机选择一个节点先喷，其余节点延后 300 ms；顺序模式会随机排列
  两侧节点，并从先喷侧开始按 300 ms 间隔左右交替，某一侧耗尽后再补完另一侧。
- 保持红线或最大转速 1 秒且没有换档后，每 275-750 ms 随机尝试一次单侧
  火焰，每次固定 20% 概率；离开转速区域或换档时立即重置。
- N 挡（游戏挡位值 1）持续轰油门时，在相同 1 秒门槛和随机间隔下将每次
  尝试概率提高到 45%；要求油门输入至少 25%，其他挡位仍保持 20%。
- 每次换档或持续红线事件都先提交火焰。游戏后端确认火焰成功后，该侧再独立
  使用 30% 概率播放音频；未抽中时只有火焰。音频不再分组，每次直接在 12 个
  WAV 槽位中进行一次均匀随机抽取，每个文件概率严格为 `1/12`。
- NOS 实际开始喷射时有 30% 概率、实际停止喷射时有 35% 概率播放左右成对
  音频；成功后随机采用同步或间隔 300 ms。状态直接追踪游戏独立的 NOS 粒子
  发射器，不再把按键输入当成喷射状态。未安装 NOS、储量耗尽或仅持续按住
  NOS 键时不会制造虚假开始/结束边沿，也不会修改 NOS 自身的视觉效果。
- 火焰脉冲持续 550 ms；发射强度保持原始的 1.0，只延长可见时间，不再
  放大火焰强度。
- v1.1.12 将音频基础增益从 1.2491325 降至 0.999306，即相对上一版统一降低
  20%；低频增厚、降调、金属共振、空间定位和环境混响比例均保持不变。
  12 份素材均加入 10 ms 等功率渐强和 120 ms 等功率渐弱，
  去掉触发与结束处的硬切。新素材转换时统一预留
  14 dB 峰值余量，避免素材响度和播放增益叠加。最终素材转换为居中单声道，
  由排气节点负责实时空间定位；声像限制为 ±0.55，并对直达声保留对侧馈送，
  修复素材通道布局与过宽声像造成的单边听感。独立环境总线的湿声相对上一版
  提高约 10.6 dB，使用更宽、更强但仍短促的早期反射与衰减尾音，使环境效果
  能够明确听见，同时不把直达爆裂声拖成长回声。混响子总线使用输出设备的
  实际采样率，不再硬编码 48 kHz，避免非 48 kHz 设备静默退回纯直达声。
  v1.1.11 把播放音高降低约 14%，以 380 Hz 为界提取低频主体并按 0.80 混回，
  再叠加约 1.45 kHz（+7 dB、Q 3.0）和 2.65 kHz（+4.5 dB、Q 4.0）两层
  金属管腔共振。处理后使用 0.78 输出补偿并把近距离低通上限收至 0.82，明显
  强化低沉、厚实和金属敲击感，同时抑制单纯的响度暴涨与过脆高频。
- 默认要求左右两个 marker 都存在。任意一个缺失时，该车不会发出排气火焰
  或回火声音；没有任何排气节点的电动车同样会被控制器和原生回调双重拦截。
- 已接管原版排气回火事件 `0/3/4`，仅在车辆左右排气节点都有效时抑制；
  NOS 使用独立发射器列表，不在抑制范围内。
- 原生兼容 Archie's SunSet 1.15.2：不再伪造原版排气方向或回火标志。SunSet
  每帧完成车辆灯光收集后，本插件只为当帧正在喷火的实际排气节点追加动态灯光；
  节点喷几次就亮几次，每次灯光与对应的 550 ms 火焰脉冲同时开始和结束。
  颜色、位置偏移、方向、角度、强度、范围和高光参数均采用 SunSet 已从
  `SunSetData/SpotLights.yml` 的 `ExhaustLight` 读取的当前配置，并沿用它的
  天气灯光亮度修正。SunSet 版本或代码签名不匹配时只关闭灯光联动，不影响
  本插件的火焰和音频。
- v1.1.15 原生 ASI 只读取已验证车辆表的 0 号玩家车槽位。AI 车辆不进入
  触发状态机，不会被本插件喷火、播放音频、添加 SunSet 排气灯光或抑制原版
  回火；AI 车继续完整使用游戏原版逻辑。渲染层只保留玩家车的一份排气/NOS
  连接记录，换车或离开赛事时自动清除旧记录和未完成脉冲。
- 正式版不再每帧扫描最多 128 个车辆槽位，也不再执行仅供诊断的根模型
  Marker 查询与字段格式化；核心 C API 仍保留多车能力，供其他适配器使用。
- 快速连续换档会追加尚未完成的成对事件；配置重载、控制器重置和显式关闭时会恢复
  仍存活车辆的原版排气回火开关。车辆消失后不会用过期 ID 回调适配层。
- v1.1.14 增加独立设备绑定门禁。插件在安装任何 Hook 前读取 SMBIOS System
  UUID、Windows `MachineGuid` 和系统卷序列号，三项缺一即拒绝。首次验证成功会在
  游戏现有的 `SCRIPTS`/`scripts` 目录生成
  `NFSMWExhaustBackfire.device.json`；确定性绑定载荷使用 Windows DPAPI
  `LOCAL_MACHINE` 模式和插件独立熵加密，JSON 只保存大写十六进制密文，不落盘
  原始硬件值。后续启动会解密并核对现有绑定；文件损坏、被篡改、来自另一台设备
  或产品载荷不匹配时均停用插件，且不会覆盖原文件。

## 当前状态

这个包已经包含完整、可测试的触发状态机、配置读取、12 槽音频清单和稳定的
C 回调接口（ABI v6，音频改为扁平 `clipIndex`，并保留既有结构大小与固定
packing）。目标游戏已锁定为
精确的 C5C5/Reforged 镜像，并只接受 `speed.exe`。插件会在安装任何 Hook 前
核验完整 MD5/SHA-256、64 字节 `NFSMWRF1` 签章、验证码 `868086`、签章记录的
原始规范 SHA-256、PE 字段和每个入口的代码签名。普通原版、仅改名或被修改的
`speed.exe` 都不会被接受。上述程序验证和设备绑定验证全部通过后才会注册核心并
安装 Hook。

现在已有可直接由 ASI Loader 加载的 Win32/x86 正式版。原生 ASI 只读取车辆表
0 号槽中的玩家车，并只接受该表项
指向主虚表为 `0x008AA9D8` 的 `PVehicle`，从 `PVehicle + 0xF4/+0xFC` 读取
 Engine 和 Transmission，并在三个虚表全部精确匹配后读取车辆的
 RPM、红线、最大 RPM、档位和换档状态；还会从 `PVehicle + 0xE8` 的输入接口
 读取油门、刹车和手刹。NOS 音频状态不采用这个接口的按键字节，而是从
 `CarRenderConn + 0x3EC` 枚举并追踪游戏实际更新的 NOS 发射器。正式版会验证
 `PVehicle + 0x108`
的 Renderable 虚表和全部七个函数地址。实机已证明直接在整车根 `IModel` 上查询
排气 Marker 会返回空。实机已确认 Renderable 所属对象能直接关联到对应的
`CarRenderConn`。本版会枚举 CarRenderInfo 排气 Marker 列表，读取每个节点关联的
名称哈希并与排气发射器逐项配对，同时转发式追踪原版单次/持续粒子调用和
`HandleFxEvent`。本版不再调用实机中返回成功但不可见的一次性效果，而是从车辆
属性 `0x60CEC115` 动态解析已确认能创建粒子的持续回火效果，并对目标侧的全部
排气口维持 550 ms 短脉冲。音频通过 32 个 XAudio2 voice 播放并加入车辆相对
空间化。当前正式版会抑制已确认的原版排气回火事件，只保留插件调度的火焰；
同时把仍处于脉冲期的实际排气节点加入 SunSet 的当帧动态灯光缓冲。NOS 粒子
路径始终不修改。

不能把未经确认的地址硬写进去：错误地址会直接崩溃。真正接入游戏时只需实现
`PluginApi.hpp` 中的六个回调，不需要改动核心状态机。已确认的目标指纹和兼容性边界
见 `docs/TARGET_PROFILE.md`。

## 安装与测试

1. 确保游戏完全退出。
2. 把 `NFSMWExhaustBackfire.asi`、`NFSMWExhaustBackfire.ini`、
   `BackfireAudio.ini` 和 `audio/backfire` 文件夹放进游戏的 `SCRIPTS` 目录。
3. 启动已经签章并包含验证码 `868086` 的 `speed.exe`。首次成功启动后确认
   `SCRIPTS/NFSMWExhaustBackfire.device.json` 已生成；这个 JSON 不随压缩包预置。
4. 再次启动游戏，确认插件能够核验并复用同一 JSON，然后进入一场可驾驶赛事。
5. 正常驾驶一段，完成数次升/降档，并持续顶住红线约 3 秒；正常使用一次
   NOS，确认实际喷射只产生一次开始和一次结束边沿，且 NOS 视觉表现没有变化。
   再用未安装 NOS 的车辆以及 NOS 已耗尽的车辆持续按键，确认没有回火声音。
6. 确认能看见同步或间隔 300 ms 的左右尾焰，并检查声音是否随车辆位置变化。
7. 安装受支持的 SunSet 1.15.2 时，在夜间确认灯光严格跟随各节点的 550 ms
   尾焰脉冲，并确认修改 `SpotLights.yml` 的 `ExhaustLight` 后两者颜色一致。

正式构建默认关闭全部文件日志与调试输出，不会创建或刷新
`NFSMWExhaustBackfire.log`。签章、PE、代码入口或设备绑定任意一项不匹配时，
插件会保持禁用且不安装 Hook，游戏继续使用原逻辑。
不要在游戏运行中热卸载或替换 ASI；安装、更新和移除都必须在游戏完全退出后
进行。常规 ASI Loader 会让插件随游戏进程保持加载，这也是当前支持的运行方式。

## 接入接口

适配层需要每帧完成这些工作：

1. 枚举有效 `PVehicle`，用稳定 ID 填充 `NfswExhaustVehicleSnapshotC`。
2. 从车辆 `IEngine` 读取当前 RPM、红线和最大 RPM，并提供换档边沿。
3. 精确查找 `LEFT_EXHAUST` 与 `RIGHT_EXHAUST`，给出 world-space 坐标和
   `qx/qy/qz/qw` 单位四元数朝向。
4. 接收带明确 `side` 的单侧 `spawnFlame` 请求并调用游戏的排气粒子系统。
5. 接收 `playAudio` 请求，按 `assetId` 播放 3D 音频。
6. 在 `setVanillaExhaustEnabled` 中只替换原版排气回火路径，不影响 NOS。

所有导出 API 都必须从同一个游戏线程调用，适配层回调不得重入 API。卸载或
销毁适配器前必须先在游戏线程调用 `NFSW_Exhaust_Shutdown()`。

详细的版本与逆向边界见 `docs/INTEGRATION_NOTES.md`，接口示例见
`docs/ADAPTER_EXAMPLE.cpp`。

## 音频接入

`audio/backfire` 已包含最终 12 个 WAV，`config/BackfireAudio.ini` 使用扁平槽位：

```text
clip01 ... clip12
```

每次播放使用标准均匀整数分布直接抽取 `clip01..clip12`，不先抽组，也没有组内
变体步骤。现有 `g1_01.wav` 等名称只是兼容旧素材文件名，不代表分组概率。
全部资源均为 PCM 单声道、44.1 kHz、16-bit、约 1.69 秒。原始 8 声道素材的
前两个有效声道已等权混合，其余静音声道不写入正式文件；具体播放由适配层负责；
每份文件带 10 ms 渐强和 120 ms 渐弱；清单必须完整填写 12 个槽，缺项或
重复项会直接拒绝加载。原始 WAV 保持不变；低频增厚、轻微降调、金属腔体
共振和高频收敛在插件加载素材及播放时实时完成。

## 配置

默认参数在 `config/NFSMWExhaustBackfire.ini`。段名只用于阅读；读取器按键名
匹配，因此可以调整段落但不能修改键名。

## 构建和测试

核心为 C++17，无第三方运行库依赖。ASI 使用 MinHook 源码；在 Visual
Studio 2022 x86 Developer Command Prompt 中指定其源码目录：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release `
  -DNFSMW_MINHOOK_DIR=C:/path/to/minhook
cmake --build build
ctest --test-dir build --output-on-failure
```

最终 ASI 必须构建为 Win32/x86；64 位 DLL 无法被 NFSMW 2005 加载。

当前 Win32 Release 构建会运行核心状态机、C 回调流程、纯 C 头文件兼容性和
签章验证测试；产物也必须核对为 x86/PE32。

换档同步模式允许左右在同一帧各提交一发；顺序模式随机决定先后侧，并把第二侧
安排在 300 ms 后。若游戏后端拒绝请求，会在该成对事件截止前重试；截止后直接
丢弃，避免形成延迟尾焰。
