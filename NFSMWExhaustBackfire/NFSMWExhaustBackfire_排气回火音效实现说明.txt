NFSMW Exhaust Backfire 排气回火音效实现说明
================================================

适用版本：v1.1.14
游戏：Need for Speed: Most Wanted (2005)
生成日期：2026-09-12


一、总体实现方式
----------------

插件没有调用游戏原版的回火音频，而是使用 Windows XAudio2 建立独立的
音频播放后端。游戏负责提供车辆状态和位置，插件负责决定何时触发、选择哪份
WAV、计算左右声像/距离衰减/低通，再把处理后的声音送到系统音频输出。

完整链路如下：

车辆遥测（RPM、挡位、油门、NOS、排气节点）
    -> 回火触发状态机
    -> 火焰请求
    -> 游戏原生排气粒子发射器确认火焰成功
    -> 独立进行 30% 音频概率判定
    -> 成功时随机选择 12 份 WAV 中的一份
    -> 根据车辆与监听车辆的位置计算空间参数
    -> XAudio2 直达声 + 短环境反射声
    -> 扬声器输出

换挡和持续红线事件遵循“火焰决定声音”的原则：只有火焰请求被游戏后端
接受后，该侧再以 30% 概率提交对应的回火音频。因此不会出现火焰失败但声音
单独播放的情况，但允许出现只有火焰而没有声音。NOS 实际开始/停止喷射边沿是
独立音频事件，不生成排气火焰，也不使用这条 30% 火焰音频概率。


二、触发与门禁
--------------

1. 全局 RPM 门槛

引擎转速必须严格大于 4000 RPM。RPM 小于或等于 4000 时：

- 换挡回火不会触发；
- 持续红线回火不会触发；
- NOS 实际开始和停止喷射的回火音频不会触发；
- 尚未播放的延迟火焰和音频会被取消；
- 原生音频回调还会再次检查 RPM，防止状态机之外的漏播。

2. 排气节点门槛

默认要求车辆同时具有 LEFT_EXHAUST 和 RIGHT_EXHAUST。缺少任意一侧时，
该车的插件火焰和插件回火音频都会被禁止并清空队列。原生火焰回调和音频
回调还会再检查一次节点状态。因此，没有任何排气节点的电动车不会播放插件
火焰或回火音效。

3. 换挡事件

每次有效升档只判定一次：

- 左右同步各一次：22.5%；
- 左右先后各一次，间隔 300 ms：17.5%；
- 完全不播放：60%。

降档使用独立规则：只要实时 RPM 严格大于 4000，每个物理降档
周期固定有 80% 概率触发；成功后仍按照 45:35 的相对权重选择同步或顺序模式。
车辆最大转速、红线比例和旧版概率插值不会再改变该 80%。不再要求油门、刹车
或手刹输入，因此松油溜车时主动降档也能触发。

左右每侧只播放一次音效，与该侧有一个还是多个排气节点无关。四尾喉车辆
不会因为四个火焰节点而把声音重复四次。

4. 持续红线事件

车辆必须连续 1 秒处于红线或最大转速区域且没有换挡，之后每 275-750 ms
随机尝试一次：

- 普通挡位：每次尝试 20%；
- N 挡且油门输入不低于 25%：每次尝试 45%。

5. NOS 边沿事件

- 游戏确认 NOS 发射器实际开始工作的瞬间：30% 概率播放；
- 游戏确认 NOS 发射器实际停止工作的瞬间：35% 概率播放；
- 未安装 NOS、NOS 已耗尽或只有按键输入：不会播放；
- 持续喷射期间：不会重复播放；
- 成功后随机选择左右同步，或左右间隔 300 ms 各播放一次。

插件在车辆渲染连接建立时枚举 `CarRenderConn + 0x3EC` 的独立 NOS 发射器，
只把这些发射器实际进入游戏连续粒子更新函数 `0x00744A50` 视为喷射活动。
最后一次真实更新后保留 180 ms 宽限，以免低帧率造成状态抖动。输入接口的
NOS 按键字节不再驱动音频，因此一直按住一个无效 NOS 键不会反复制造边沿。


三、12 份音效的扁平随机选择
------------------------------

12 份 WAV 不再分组，直接映射到 12 个扁平槽位：

clip01 -> audio/backfire/g1_01.wav
clip02 -> audio/backfire/g1_02.wav
clip03 -> audio/backfire/g1_03.wav
clip04 -> audio/backfire/g2_01.wav
clip05 -> audio/backfire/g2_02.wav
clip06 -> audio/backfire/g2_03.wav
clip07 -> audio/backfire/g3_01.wav
clip08 -> audio/backfire/g3_02.wav
clip09 -> audio/backfire/g3_03.wav
clip10 -> audio/backfire/g4_01.wav
clip11 -> audio/backfire/g4_02.wav
clip12 -> audio/backfire/g4_03.wav

每次实际播放时，程序使用 `std::uniform_int_distribution(0, 11)` 一步抽取一个
槽位，不做“先抽组、再抽组内变体”的两阶段选择，也不再使用随机数 `% 12`。
因此每个 WAV 的概率严格为 `1/12`。

左右各自播放时会分别随机选择，所以左右可能抽到相同 WAV，也可能抽到不同
WAV。这可以减少连续事件完全相同造成的机械重复感。

BackfireAudio.ini 负责声明 12 个扁平槽位映射。当前原生加载器在插件初始化时
预载固定命名的 g1_01.wav 至 g4_03.wav，因此正式包应保持现有目录结构和文件名。


四、WAV 的加载方式
------------------

插件启动时一次性把 12 份音效读入内存，避免比赛中触发回火时临时访问磁盘。

当前加载要求：

- RIFF/WAVE 容器；
- PCM 格式；
- 必须包含有效的 fmt 和 data 块；
- 单个文件最大 16 MiB；
- 声道数、采样率、块对齐和位深必须有效；
- 路径必须位于插件目录下，拒绝绝对路径和“..”目录跳转。

v1.1.13 随附的 12 份正式资源统一为 44.1 kHz、16-bit、单声道 PCM，时长约
1.69 秒。用户提供的源文件是 8 声道 WAVE_FORMAT_EXTENSIBLE，但只有前两个
声道包含信号；构建正式资源时把这两个有效声道等权混合为居中单声道，舍弃
六个静音声道。这样既满足当前 PCM 加载器，也避免 WAV 自带声道布局把整个
回火声固定推向某一侧；最终左右位置完全由车辆排气 marker 决定。由于源素材
平均响度很高且多份峰值已达到 0 dBFS，正式转换还会统一衰减 14 dB，避免与
插件基础增益叠加后产生上一版约四倍的异常听感，同时保留各素材原有响度差异。
每份正式 WAV 另带 10 ms 等功率渐强和 120 ms 等功率渐弱，让爆裂声快速建立，
再自然收尾，避免独立音频后端启动和停止时出现生硬切口。

v1.1.11 不重写随包 WAV，而是在加载和播放时把音色处理明显加强：以 380 Hz
为界提取低频主体并按 0.80 比例混回，播放频率比设为 0.86（约降低 14% 音高），
先在 1.45 kHz 加入 +7 dB、Q 3.0 的金属管体共振，再在 2.65 kHz 加入
+4.5 dB、Q 4.0 的较窄金属振铃，并把近距离低通上限限制为 0.82。处理结果在
写回 PCM 前乘 0.78 作输出补偿并继续限幅。这样会刻意呈现更低沉、厚实、浑厚
且明显的金属排气管质感，同时避免所有增强能量直接变成失控的音量暴涨。

任意一份正式 WAV 缺失或格式无效时，音频后端不会进入 ready 状态，以避免
只加载部分素材后产生不可预测的随机缺音。


五、XAudio2 播放与并发管理
------------------------

插件创建：

- 1 个 XAudio2 引擎；
- 1 个 Mastering Voice，连接系统实际输出设备；
- 最多 32 个 Source Voice，用于多个短回火声重叠播放；
- 1 个可选的双声道短混响 Submix Voice。

播放时优先复用已经结束的 Voice。32 个 Voice 全部繁忙时，会停止并回收最早
使用的 Voice，再播放最新事件。这样可以限制资源占用，也防止极端情况下无限
创建音频对象。


六、音量和空间定位
------------------

1. 基础音量

当前基础增益为 0.999306，即在 v1.1.11 的 1.2491325 基础上统一降低 20%。
音色滤波、空间定位和环境混响比例不变。最终直达声音量为：

最终音量 = 0.999306 x 距离增益

本车声音的距离增益为 1.0。其他车辆根据距离衰减：

距离增益 = 1 / (1 + (距离 / 22)^2)

远处车辆的增益最低限制为 0.04，避免声音突然完全消失。

2. 声源位置

音频请求携带左侧或右侧排气 marker 的局部坐标。插件使用车辆世界矩阵把它
转换为世界坐标，再与监听车辆位置比较。因此声音的位置来源是实际排气节点，
不是屏幕中央或固定背景声源。

3. 左右声像

正式 WAV 为居中单声道，插件把“声源到监听者”的方向投影到监听车辆横向轴上，
得到左右声像。空间计算先缩放到 60%，再限制在 -0.55 到 +0.55 之间；直达输出
进一步使用 70% 声像强度并保留对侧馈送，避免回火被推到单个声道。定位信息
不可用时，使用保守回退值：

- LEFT_EXHAUST：-0.18；
- RIGHT_EXHAUST：+0.18。

直达声只送往前左/前右声道，不把同一份干声复制到所有扬声器，从而避免声音
像铺在整个背景中的音乐。

4. 距离低通

其他车辆越远，高频衰减越明显：

低通参数 = 0.55 + 0.45 x 距离增益

近距离时接近 1.0，保留完整的爆裂细节；远距离时逐渐趋近 0.55，使声音更暗，
模拟空气传播和环境遮蔽带来的高频损失。


七、环境融合与短混响
--------------------

每个回火 Source Voice 同时发送到两条路径：

1. 直达路径：直接进入 Mastering Voice，保留清晰位置和瞬态；
2. 环境路径：进入 XAudio2 Reverb，再以 0.52 的总增益混入输出。

混响以 XAudio2 的 ALLEY 预设为基础，但改成较短的赛道反射参数：

v1.1.11 使用 Mastering Voice 报告的实际输出设备采样率创建混响子总线，不再
固定使用 48 kHz。这避免 44.1/96 kHz 等设备因处理级采样率不匹配而无法建立
混响、最终只剩直达声的问题。

- WetDryMix：100%（该总线只输出湿声）；
- Room：-1300；
- RoomHF：-2300；
- DecayTime：0.95 秒；
- Reflections：-500；
- ReflectionsDelay：0.015 秒；
- Reverb：-850；
- ReverbDelay：0.025 秒；
- Diffusion：68%；
- Density：75%。

湿声只使用原始声像的 18%，因此反射声更宽、更不集中。立体声输出的湿声
矩阵也从 0.35 提高到 0.55；配合 0.52 的混响总线增益，湿声相对 v1.1.4
提高约 10.6 dB，环境效果不再被直达声完全掩盖。立体声输出主要进入左右
声道；4/5.1/7.1 输出时，会把更高比例的环境声送到后置或
环绕声道，让爆裂声具有短促的场地反射，而不是简单叠加一份延迟干声。

如果系统无法创建 Reverb 效果，插件仍可只用直达路径播放，不会因此停止整个
音频功能。


八、火焰与音频的一致性
----------------------

换挡和持续红线的调用顺序固定为：

1. 检查 RPM 和排气节点；
2. 选择左右侧和喷射模式；
3. 向游戏原生粒子发射器提交火焰；
4. 只有火焰返回成功，才进行同一侧的 30% 音频概率判定；
5. 抽中后选择 WAV，音频请求携带相同车辆 ID、侧别、marker 和计划时间。

因此，音频与火焰在车辆、左右侧和事件时间上绑定。火焰失败、marker 消失、
车辆状态失效或 RPM 降到 4000 以下时，声音不会脱离火焰单独出现。


九、当前实现的边界
------------------

音频目前运行在独立 XAudio2 后端，并没有注入 NFSMW 原生音效总线。这意味着：

- 可以根据车辆位置实现距离、左右声像和低通；
- 可以模拟短促的赛道反射和环绕输出；
- 但无法读取游戏每条赛道的原生混响区域；
- 无法自动继承游戏隧道、建筑遮挡、摄像机混音和全局音效总线压缩；
- 游戏内“音效音量”设置不一定能直接控制该独立后端。

当前的“跟车”和“环境融合”来自插件自行计算的空间参数与短混响，而不是游戏
原生声学系统。这是理解听感上限和后续优化方向时最重要的一点。
