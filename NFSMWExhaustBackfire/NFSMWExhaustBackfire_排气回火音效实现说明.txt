NFSMW Exhaust Backfire 排气回火音效实现说明
================================================

适用版本：v1.1.46
游戏：Need for Speed: Most Wanted (2005)
生成日期：2026-09-30


一、总体实现方式
----------------

插件没有调用游戏原版的回火音频事件，但已经移除独立 XAudio2 输出。游戏负责
提供车辆状态和位置，插件负责决定何时触发、选择哪份 WAV、计算左右声像、
距离衰减和低通，再把处理后的声音直接混入游戏最终的 16-bit PCM 数据流。

完整链路如下：

车辆遥测（RPM、挡位、油门、排气节点）
    -> 回火触发状态机
    -> 火焰请求
    -> 游戏原生排气粒子发射器确认火焰成功
    -> 按场景和成功喷火侧独立进行音频概率判定
    -> 成功时按排气节点总数生成 1-6 个独立 16 选 1 的音效 cue
    -> 根据车辆与监听车辆的位置计算空间参数
    -> 32 槽软件 voice 的直达声 + 户外反射声
    -> 游戏活跃 PCM 渲染函数 0x0082049E
    -> 游戏 DirectSound 缓冲区与扬声器输出

换挡和持续红线事件遵循“火焰决定声音”的原则：只有火焰请求被游戏后端
接受后，该侧才按场景概率判定音频。升档侧为 50%，降档侧为 70%，持续红线
或 N 挡轰油门为 30%。同一成对喷火事件中，两侧各自判定，但只要任意一侧
成功就生成一次完整音效批次；另一侧不会重复生成第二批。因此不会出现火焰
失败但声音单独播放的情况，但允许出现只有火焰而没有声音。


二、触发与门禁
--------------

1. 全局 RPM 门槛

引擎转速必须严格大于 4000 RPM。RPM 小于或等于 4000 时：

- 换挡回火不会触发；
- 持续红线回火不会触发；
- 尚未播放的延迟火焰和音频会被取消；
- 原生音频回调还会再次检查 RPM，防止状态机之外的漏播。

2. 排气节点门槛

默认要求车辆同时具有 LEFT_EXHAUST 和 RIGHT_EXHAUST。缺少任意一侧时，
该车的插件火焰和插件回火音频都会被禁止并清空队列。原生火焰回调和音频
回调还会再检查一次节点状态。因此，没有任何排气节点的电动车不会播放插件
火焰或回火音效。

3. 换挡事件

每次有效升档只判定一次：

- 左右同步各一次：33.75%；
- 左右先后各一次，间隔 300 ms：26.25%；
- 完全不播放：40%。

降档使用独立规则：只要实时 RPM 严格大于 4000，每个物理降档
周期固定有 80% 概率触发；成功后仍按照 45:35 的相对权重选择同步或顺序模式。
车辆最大转速、红线比例和旧版概率插值不会再改变该 80%。不再要求油门、刹车
或手刹输入，因此松油溜车时主动降档也能触发。

成功生成音效批次后，播放数量由左右排气节点总数决定：

- 左右各 1 个、共 2 个节点：随机播放 1-2 个音效；
- 左右各 2 个、共 4 个节点：随机播放 2-4 个音效；
- 左右各 3 个或更多、共 6 个或更多节点：随机播放 3-6 个音效；
- 非对称布局使用通用规则：最少为节点数一半向上取整且不超过 3，最多为
  节点数且不超过 6。

同一批次从 16 份素材中无放回抽取，每个音效都不同。多个音效以 50% 概率
同时播放或依次播放；2 节点车辆依次播放时相隔 300 ms，4 节点车辆相隔
200 ms，6 个及以上节点相隔 100 ms。左右声源按照车辆真实左右节点数量
无放回分配。

4. 持续红线事件

车辆必须连续 1 秒处于红线或最大转速区域且没有换挡，之后每 275-750 ms
随机尝试一次：

- 普通挡位：每次尝试 40%；
- N 挡且油门输入不低于 25%：每次尝试 70%。

三、16 份音效的扁平随机选择
------------------------------

16 份 WAV 不分组，直接映射到 16 个扁平槽位：

clip01 -> audio/backfire/g1_01.wav
clip02 -> audio/backfire/g1_02.wav
clip03 -> audio/backfire/g1_03.wav
clip04 -> audio/backfire/g2_01.wav
clip05 -> audio/backfire/g2_02.wav
clip06 -> audio/backfire/g2_03.wav
clip07 -> audio/backfire/g3_01.wav
clip08 -> audio/backfire/g3_02.wav
clip09 -> audio/backfire/g3_03.wav
clip10 -> audio/backfire/g4_01.wav
clip11 -> audio/backfire/g4_02.wav
clip12 -> audio/backfire/g4_03.wav
clip13 -> audio/backfire/g5_01.wav
clip14 -> audio/backfire/g5_02.wav
clip15 -> audio/backfire/g5_03.wav
clip16 -> audio/backfire/g5_04.wav

每一条真正提交播放的音频 cue 都独立从 16 个槽位中均匀抽取一次。算法不做
“先抽组、再抽组内变体”的两阶段选择，也不使用洗牌袋、上一条排除或同批
去重；每份 WAV 在每次实际播放时概率都严格为 1/16。独立随机允许连续两次
或同一多 cue 批次中抽到相同素材，这是预期行为而不是漏随机。

BackfireAudio.ini 负责声明 16 个扁平槽位映射。v1.1.26 原生加载器会解析这份
清单，并按每个 clip 实际填写的相对路径预载 WAV，不再依赖写死的 g1_01.wav 至
g5_04.wav 文件名。路径仍必须位于插件目录内，且 16 个槽位必须完整、唯一。


四、WAV 的加载方式
------------------

插件启动时一次性把 16 份主音效和 IN/OUT 两份背景音读入内存，避免比赛中触发
回火时临时访问磁盘。

当前加载要求：

- RIFF/WAVE 容器；
- PCM 格式；
- 必须包含有效的 fmt 和 data 块；
- 单个文件最大 16 MiB；
- 声道数、采样率、块对齐和位深必须有效；
- 路径必须位于插件目录下，拒绝绝对路径和“..”目录跳转。

v1.1.37 随附的 18 份正式资源统一为 48 kHz、16-bit、单声道 PCM。16 份主回火
素材约 1.344 秒，IN/OUT 约 0.85 秒。用户提供的新源文件是 48 kHz 立体声；构建正式资源时把左右声道等权
混合为居中单声道并去除直流偏移。这样既满足当前 PCM 加载器，也避免 WAV
自带声道布局把整个回火声固定推向某一侧；最终左右位置完全由车辆排气 marker
决定。每份素材独立归一化到 -14 dBFS 峰值余量，避免与插件基础增益和实时
音色处理叠加后削波，同时保留每份素材内部原有的瞬态和动态变化。
每份正式 WAV 另带 10 ms 等功率渐强和 120 ms 等功率渐弱，让爆裂声快速建立，
再自然收尾，避免软件 voice 启动和停止时出现生硬切口。

v1.1.26 不重写随包 WAV，而是在加载和播放时使用较温和的统一音色处理：以
380 Hz 为界提取低频主体并按 0.60 比例混回，播放频率比设为 0.90（约降低
10% 音高），在 1.45 kHz 加入 +4.5 dB、Q 3.0 的金属管体共振，再在 2.65 kHz
加入 +2.5 dB、Q 4.0 的金属振铃，并把近距离低通上限放宽到 0.90。处理结果在
写回 PCM 前乘 0.82 作输出补偿并继续限幅。这样仍保留低沉和金属排气管质感，
同时减少统一处理对 16 份素材自身瞬态和频谱差异的遮盖。

音色处理后，插件对 16 份主回火 PCM 强制施加 8 ms 等功率渐入，并保持前
50% 原幅度；从素材播放进度 50% 开始等功率渐弱，在素材最后一帧归零。该包络
位于原生加载链路，因此用户替换清单中的 WAV 时也会按其实际总时长自动计算。

IN.wav 与 OUT.wav 使用和主回火素材相同的输入标准：原始 48 kHz 立体声先等权
混合为居中单声道、去除直流偏移、归一化到 -14 dBFS，并做 10/120 ms 素材级
包络；加载时继续接受实时音色处理和原有 8/180 ms 包络，不应用主回火新增的
后半程长渐弱。每播放一条主回火音频，
IN 从第 0 帧按 0.30 比例混入，OUT 从主音频总帧数的 50% 处按 0.24 比例混入。
三层声音预先合成为一条 PCM 并使用同一个软件 voice，因此共享完全一致的
排气 marker 声像、距离衰减、低通和环境混响，不会出现独立背景声漂移或脱离车辆。

任意一份主音频或 IN/OUT 缺失、格式无效或格式不一致时，音频后端不会进入
ready 状态，以避免
只加载部分素材后产生不可预测的随机缺音。


五、游戏 PCM 播放与并发管理
--------------------------

插件不再创建任何系统音频引擎或输出设备，而是维护最多 32 个固定软件 voice。
每个 voice 只保存素材指针、播放位置、音量、声像、低通状态和序号。32 槽全部
繁忙时，会回收最早使用的槽位来播放最新事件，限制极端情况下的并发成本。

游戏活跃输出循环 0x00820907 锁定 DirectSound 当前写入区域后，会调用
0x0082049E 生成这一批 PCM。插件先调用原函数完成引擎声、胎噪声、碰撞声等
游戏混音，再在返回前追加回火 voice，并从已验证的游戏全局量读取：

- 当前声道数：0x009C205F + 0x009C2060；
- 输出采样率：0x009C2046。

帧数由 0x0082049E 的第二个实参提供。仅接受 16-bit、1-8 声道、8-192 kHz
的有效提交。热路径使用固定 voice 数组和
栈上声道累加器，不创建 Voice、不访问文件、不分配临时堆内存。


六、音量和空间定位
------------------

1. 基础音量

当前基础增益为 0.710992，即在 v1.1.42 的 0.789991 基础上再降低 10%。
该总增益同时作用于主回火、IN 和 OUT 合成后的最终声源，音色滤波、
混响及三层相对比例不变。最终直达声音量为：

最终音量 = 0.710992 x 距离增益

本车声音的距离增益为 1.0。其他车辆根据距离衰减：

距离增益 = 1 / (1 + (距离 / 22)^2)

远处车辆的增益最低限制为 0.04，避免声音突然完全消失。

2. 声源位置

音频请求携带左侧或右侧排气 marker 的局部坐标。插件使用车辆世界矩阵把它
转换为世界坐标，再与监听车辆位置比较。因此声音的位置来源是实际排气节点，
不是屏幕中央或固定背景声源。

3. 左右声像

正式 WAV 为居中单声道，插件把“声源到监听者”的方向投影到监听车辆横向轴上，
得到左右声像。空间计算先缩放到 60%，再限制在 -0.55 到 +0.55 之间；直达输出
进一步使用 100% 声像强度；只有声源真正处于极限侧方时才会完全落到单侧。
定位信息
不可用时，使用保守回退值：

- LEFT_EXHAUST：-0.18；
- RIGHT_EXHAUST：+0.18。

直达声只送往前左/前右声道，不把同一份干声复制到所有扬声器，从而避免声音
像铺在整个背景中的音乐。

4. 距离低通

其他车辆越远，高频衰减越明显：

低通参数 = 0.55 + 0.45 x 距离增益

近距离时接近 1.0，保留完整的爆裂细节；远距离时逐渐趋近 0.55，使声音更暗，
模拟空气传播和环境遮蔽带来的高频损失。


七、环境融合与短混响
--------------------

每个回火软件 voice 同时计算两条路径：

1. 直达路径：直接混入游戏 PCM，保留清晰位置和瞬态；
2. 环境路径：使用稀疏户外反射抽头，再以 1.152 的总增益混入同一 PCM。

反射使用游戏当批 PCM 的实际采样率计算延时，不固定为 48 kHz。主要反射位于
110 ms 和 180 ms，后续在 330/520/800/1180/1700/2300 ms 逐级衰减，并交替
扩展左右方向，保留低密度开阔场地听感而不创建第二条输出链路。

湿声使用原始声像的 100%，让反射方向和车辆排气位置更容易辨认。立体声输出的
湿声矩阵保持 1.0；配合 1.152 的反射增益、低密度和明显延迟，
形成与直达爆裂声分离的户外远端反射及开阔尾声。立体声输出主要
进入左右声道；4/5.1/7.1 输出时，会把更高比例的环境声送到后置或
环绕声道，让爆裂声具有短促的场地反射，而不是简单叠加一份延迟干声。

该反射完全由固定计算完成，不依赖系统 Reverb 组件。


八、火焰与音频的一致性
----------------------

换挡和持续红线的调用顺序固定为：

1. 检查 RPM 和排气节点；
2. 选择左右侧和喷射模式；
3. 向游戏原生粒子发射器提交火焰；
4. 只有火焰返回成功，才按升档 50%、降档 70% 或持续事件 30% 判定该侧；
5. 任意一侧抽中后生成一次节点规模音效批次，并为每个请求绑定实际左右 marker。

因此，音频与火焰在车辆、左右侧和事件时间上绑定。火焰失败、marker 消失、
车辆状态失效或 RPM 降到 4000 以下时，声音不会脱离火焰单独出现。


九、当前实现的边界
------------------

音频现在注入 NFSMW 活跃的最终 PCM 渲染路径。这意味着：

- 可以根据车辆位置实现距离、左右声像和低通；
- 与引擎、胎噪、打滑、碰撞和警笛共用 DirectSound 缓冲、设备时钟和提交节奏；
- 可以模拟短促的赛道反射和环绕输出；
- 但无法读取游戏每条赛道的原生混响区域；
- 无法自动继承游戏在此接入点之前已完成的隧道、建筑遮挡和逐声源处理；
- 这不是把自定义 WAV 注册成 ABK/NFSMixMaster 原生事件，游戏音效滑杆是否在
  最终 DirectSound 缓冲上继续生效取决于游戏当前输出设置。

当前的“跟车”和户外反射仍由插件计算，但最终输出已与游戏所有声音合流，不再
由 Windows 在游戏之外合并第二个 XAudio2 播放端。这里是真正写入游戏正在使用
的 PCM 缓冲区，但接入时点在游戏原生逐声源环境处理之后，所以仍可能比原生
车辆音效更像后叠加声。这个边界必须与完整 ABK/NFSMixMaster 3D 声源注册区分开。


十、v1.1.32 性能优化
--------------------

该版本不改变任何触发概率、随机顺序、火焰时序、音频参数或 SunSet 灯光结果：

- 没有正在播放的回火声时，游戏 PCM 回调直接返回；
- 有声音时只遍历活跃 voice，并缓存仅随输出采样率变化的固定计算；
- 火焰服务只扫描当前活跃的排气节点；
- SunSet 在没有活跃火焰时不读取配置和灯光缓冲，有火焰时一次读取现有灯光，
  再在本地完成去重。

这些改动只减少空转检查、重复浮点计算和 VirtualQuery/内存读取次数。32 个 voice、
8 个户外反射抽头、各节点发射器调用顺序和音频混合累加顺序均保持不变。

v1.1.33 将活跃 voice 位图和正在入队的播放请求计数合并进同一个 64 位原子
状态。PCM 回调只有读取到完整状态为零时才执行空闲快速返回，从而避免播放线程
与 PCM 线程恰好交错时把首个音频缓冲延迟一轮。

v1.1.34 新增 [BackfireToneByVehicle] 车型音色表。键名使用
pvehicle/default/cars/racers 下的车辆 Collection 名且忽略大小写，支持
"collection 0.5" 和 "collection=0.5" 两种写法。默认 1.0，有效范围 0.0 到
2.0：较小值降低回放音高、加强低频主体并抑制高频瞬态，较大值提高回放音高并
强化高频瞬态；它不是直接音量倍率。原生适配层从 PVehicle+0xD4 读取 Attrib
Collection，沿 +0x10 父链读取 +0x20 Collection key，最多 16 层，并只在玩家
换车或 Collection 改变时重算。未配置或解析不到时保持 1.0，AI 车辆仍不处理。

v1.1.35 将小于 1.0 的低沉塑形提高到上一版的 135%，并按低沉程度加入连续
响度补偿：1.0 为 1.0 倍、0.1 为约 1.8775 倍、0.0 为 2.0 倍，且不再额外压低
低沉音色的混响。大于 1.0 的高频瞬态塑形提高到上一版的 275%，2.0 对应的
音高提升从 8% 增至 20%。1.0 仍严格保持中性，不影响触发、随机、素材或空间
混响参数。

v1.1.37 将试听版的 16 份主回火素材转为正式素材，并采用用户提供的 130 车
Collection 配置。低于 1.0 时，在 v1.1.35 补偿曲线上再乘
`1 + 0.10 * 低沉程度^2`：0.0 从 2.0 倍提高到 2.2 倍，0.1 从约 1.8775 倍
提高到约 2.0296 倍，1.0 仍为 1.0 倍。高于 1.0 时，高频瞬态增强系数从
2.2 提高到 4.5，低频削减系数从 0.275 提高到 0.65，最大升调从 20% 提高到
30%，使较高配置值呈现更明显的 JDM 式清脆短促爆裂感。

v1.1.44 尾气烟雾改为专用数据库效果。随包的
NFSMWExhaustBackfire-Smoke.nfsms 复制原版两个 emitter 作为独立的新节点，
把每个 emitter 的粒子数降到 2、寿命降到约 0.55 秒、最大尺寸降到约 1.05，
并改成低透明度浅灰白。两个 emitter 合成的单节点总量约为 4 个粒子，相比原版
约 24 个粒子、2 秒寿命明显更白、更稀、更短。新 emittergroup 名为
fxcar_backfire_smoke_soft，游戏哈希为 0x893908DB。

插件仍抑制原版 CarRenderConn 回火事件 0/3/4，避免原版同步喷火判定与插件触发
重复。实际选中某个玩家排气节点并到达该节点喷射时刻后，插件在同一 emitter
上单次提交专用尾气效果；770 ms 主火焰仍由 NOSEffect 的持续发射器链路驱动。
因此烟雾服从插件的左右选择、同步/顺序模式和多节点 300 ms 间隔。AI 车辆不进
插件状态机，新脚本也不修改原版 fxcar_exhaust_bmw，所以 AI 和其他原版效果
保持原样。未导入 NFSMS 时不会回退到 v1.1.43 的原版浓烟，只缺少尾气层，主
火焰、音频和 SunSet 灯光不受影响。

安装时必须先让游戏完全退出，再用 NFS-VltEd 打开游戏目录，导入
NFSMWExhaustBackfire-Smoke.nfsms 并保存数据库；随后才把 ASI、INI、音频清单
和 audio/backfire 放入 SCRIPTS。INI 的 [ExhaustSmoke] enabled=0 可关闭尾气，
intensity=0.0-2.0 可调发射强度，v1.1.45 默认值为 1.15。

v1.1.45 修复 v1.1.44 的持续烟尾问题。旧专用 emitter 从原版继承了
IsOneShot=False；通过 EmitOneShot 启动后，粒子系统仍把它作为持续发射器维护，
车辆移动时便会在先前世界坐标持续留下烟雾。新版 V2 emitter 明确写入
IsOneShot=true，使每次回火只产生一次有限粒子批次，已有粒子仍按约 0.55 秒
寿命自然消散。默认 intensity 从 1.00 提高到 1.15，浓度增加 15%；Size 四段
从 0.28/0.45/0.75/1.05 整体提高 20% 至 0.336/0.54/0.90/1.26。

为兼容已经导入 v1.1.44 的数据库，v1.1.45 使用新节点
emcar_backfire_smoke_soft_v2_1、emcar_backfire_smoke_soft_v2_2 和新效果
fxcar_backfire_smoke_soft_v2（哈希 0x00ED3E93）。因此可直接再次导入同名新版
NFSMS；旧节点可以保留但不会再被插件调用，AI 和原版效果仍不受影响。

v1.1.46 根据实机视频继续修复烟雾在生成位置停留约 3-5 秒的问题。V2 虽已
设置 IsOneShot=true，但仍继承 OnCycle=0 的无限活动窗口。V3 同时限制
IsOneShot=true、OnCycle=0.05 秒、OnCycleVariance=0、OffCycle=0，并把粒子
寿命缩短为 0.45±0.05 秒。浓度 1.15 与放大 20% 的尺寸曲线保持不变。

本版使用 emcar_backfire_smoke_soft_v3_1、emcar_backfire_smoke_soft_v3_2 和
